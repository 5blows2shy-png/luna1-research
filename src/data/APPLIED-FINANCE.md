Project metadata and artifacts live in `applied-finance-projects.ts`. The project pages and profile previews render this registry automatically. It extends the existing `ResearchDocument` availability / URL contract; it does not create a separate upload system or bypass admin access.

To attach a real artifact, add an entry with title, type, description, ISO date, file format, version, file name, optional file size, status `available`, and an HTTPS URL or a repository-owned `/downloads/...` path. Keep missing artifacts `in-progress`, with null URL/date. The UI withholds unsafe and unpublished links. React renders descriptions as text; no HTML or MDX is accepted.

Supported types: Excel Workbook, Power BI Dashboard, PDF Case Study, PowerPoint, Screenshot, Financial Model, Research Memo, Data Source, Python Notebook, SQL Analysis. A notebook attachment does not introduce a Python Lab section.

Before publishing: verify the file exists and is authorized for public distribution, remove employer/private information, attach source records for sourced claims, and confirm the artifact date and version. Only mark a project `Completed` after completed evidence exists. `Case Study` is also supported. Do not replace placeholders with fabricated screenshots or links.

The data-center model now uses annual-period, after-tax project finance schedules. The starting $50M is development CapEx, before an editable contingency, financing fees, and sponsor-funded construction interest. Debt leverage applies to CapEx plus contingency; sponsor equity balances all construction-period uses. CapEx/debt draws occur in equal installments at time zero and successive construction year-ends. Interest uses beginning debt; construction has principal grace. Operating debt term includes additional principal grace and supports equal principal, annuity, and balloon amortization. Term cannot exceed operating useful life.

CFADS = EBITDA − levered cash taxes − increase in working capital − maintenance CapEx. Taxes use straight-line depreciation on a configurable share of development cost. No tax-loss carryforwards, interest deduction limits, or depreciation on maintenance CapEx are modeled. Unlevered project cash uses taxes before the interest deduction. Equity cash includes financing, fees, repayment, and levered taxes. Terminal gains above residual book value are taxed; disposal losses receive no tax relief. Working capital is released at exit. Exit cash is excluded from CFADS, DSCR, and payback. No reserve account, cash sweep, default waterfall, refinancing, or decommissioning model is implied.

DSCR = operating CFADS / cash interest and principal. Construction and zero-service years are N/A. Minimum/average include operating debt-service periods only; average is arithmetic. The coverage threshold is an editable user assumption, not a lender covenant. Project NPV is unlevered and independent of financing. IRR is withheld for nonconventional sign patterns. Scenarios and all three sensitivities use the same deterministic engine. Input edits remain session-only.

The eight-screen recruiting mode uses the current selected scenario; its downside and sensitivities derive from the editable base. Print CSS isolates these eight screens for a PDF preview. Completed PDF and formula-based Excel artifacts are attached under public/downloads. The PDF captures the starting base case; workbook inputs are independent of on-page edits. `projectFinanceExport` in `src/lib/project-finance-report.ts` provides a versioned, serializable schedule contract. Workbook outputs were reconciled to the engine for Base, Upside and Downside cases. Public industry context is sourced to the IEA and never treated as a model input.

The nonprofit example is synthetic cash-basis data. Revenue equals collections; expenses equal payments. Restricted and unrestricted cash bridges reconcile. It is not an accrual model or an employer dashboard.
